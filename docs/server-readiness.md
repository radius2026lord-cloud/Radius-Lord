# جاهزية الخوادم

تاب المدير الرئيسي ضمن الخوادم والبنية التحتية. يعرض MySQL واتصالات Ubuntu/SSH وخدمات FreeRADIUS وبوابات OpenVPN المحفوظة؛ الخدمات على الجهاز نفسه تظهر منفصلة.

الفحص يبدأ تلقائيًا مع الخلفية، والفاصل الافتراضي خمس دقائق. يمكن اختيار 1 أو 5 أو 10 أو 15 أو 30 أو 60 دقيقة. الجدول محفوظ في القاعدة المركزية ضمن server_readiness ولا يتطلب ترحيلًا جديدًا. النتائج محفوظة وتُقرأ من الصفحة كل خمس ثوانٍ دون إعادة إجراء الفحوص من المتصفح. يستمر الفحص عند إغلاق الصفحة ما دامت الخلفية تعمل. قفل MySQL يمنع تداخل جولتين حتى عند تشغيل أكثر من عملية خلفية.

نسبة الاجتياز = عدد الفحوص الناجحة / عدد الفحوص المنفذة. الجاهز يجتاز جميع فحوص الخدمة؛ نتيجة قديمة أو إعداد متغير لا تُعرض كجاهزية حالية. الموارد لا تدخل في هذه النسبة، والقياسات غير المتاحة تظهر صراحة. مدة الفحص تشمل اتصالاته وعملياته ولا تمثل زمن ping.

- MySQL: الاتصال، MySQL 8، سعة الاتصالات الحالية واستقبال البيئات. استهلاك الاتصالات من Threads_connected/max_connections. لا ينشئ هذا التاب قواعد أو مستخدمين للفحص؛ فحص صلاحيات التوليد الكامل يظل في صحة البنية التحتية.
- Ubuntu/SSH: اتصال SSH موثوق بالمفتاح المحفوظ، وقراءة CPU والذاكرة وقرص الجذر بأمر Python ثابت للقراءة فقط. يلزم Python 3. لا تُشغّل أوامر يقدمها المستخدم.
- FreeRADIUS: الخدمة والإعداد عبر SSH، مصادقة حساب الاختبار، محاسبة والتحقق من السجل في القاعدة المحددة. قد تظهر سجلات اختبار جديدة في الخدمة وقاعدة الاختبار؛ لا تُعدّل الخدمة ولا تُعاد تشغيلها من تاب الجاهزية.
- OpenVPN: API والموارد، خدمة تعمل وتطابق المنفذ والشهادة وPPP Profile، وتفعيل وتجهيز محفوظان. فحص نفق فعلي وسعة النطاق الكامل يتمان عبر فحوص التوليد القائمة.

القراءة والعمليات خاصة بالمدير الرئيسي، وطلبات الفحص وتعديل الفاصل تتحقق من Origin. لا تُعاد الأسرار أو أخطاء الخوادم الخام للواجهة. تغيير الإعدادات يُبطل عرض التقرير السابق حتى الجولة التالية. جاهزية التاب مؤشر مراقبة ولا تتجاوز بوابة صحة البنية التحتية قبل التوليد.

التحقق في بيئة التطوير: فحص TypeScript للواجهة والخلفية. تجربة الشبكة الفعلية يقوم بها المستخدم.
