# قاعدة شبكة العميل — أساس SQL، المرحلة الأولى

الملف: `src/app/backend/tenant-schema/001_foundation.sql`.
هدفه MySQL 8.0.46 في قاعدة جديدة معزولة للشبكة؛ ليس ترحيلًا للقاعدة المركزية أو قاعدة عميل قديمة.
لا يحتوي CREATE DATABASE أو بيانات اتصال أو مستخدمين افتراضيين أو تفعيل اشتراك.
لم يُنفذ على قاعدة تشغيل ولم تُشغل اختبارات، وفق تعليمات المشروع.

## الجداول المنفذة في القالب

| الجدول | المسؤولية |
|---|---|
| network_settings | سجل واحد للاسم والوصف والرقم الرئيسي، تفعيل التقاط الهوية وسياسة الاستحقاق العامة |
| network_contact_numbers | أرقام إضافية اختيارية دون تكرار داخل الشبكة |
| platform_subscription | النسخة الحالية فقط من اشتراك المنصة والرخصة وحدود PPPoE وNAS والتواريخ والمزامنة |
| time_units | دقيقة، ساعة، يوم، أسبوع، شهر؛ الشهر تقويمي وليس 30 يومًا ثابتًا |
| managers | رئيسي واحد كحد أقصى، ومدراء فرعيون؛ حسابات الإدارة منفصلة عن مستخدمي RADIUS |
| permission_groups | مجموعات مسماة للصلاحيات، دون جداول roles مكررة |
| permissions | تعريف العمليات وقيد العمليات الحصرية للرئيسي |
| permission_group_permissions | مجموعة متعددة الصلاحيات؛ الفرعي مرتبط بمجموعة واحدة |
| customers | الاسم والكنية، عنوان نصي وإحداثيات اختيارية، المدير المسؤول وكود الدفع الدائم |
| customer_identity_documents | وثيقة واحدة اختيارية للعميل، جميع الحقول التي حسمناها وصورتاها |
| address_keywords | اقتراحات أسماء الأماكن؛ ليست مناطق تغطية ولا حقل منطقة إلزاميًا للعميل |
| customer_categories | تصنيفات للتنظيم والبحث، تابعة لمدير |
| customer_category_memberships | تصنيفات متعددة للعميل، مع فرض تطابق المدير في SQL |
| activity_log | سجل الإجراءات ونتائجها والمنفذ وسياق العميل والقيم المرشحة قبل/بعد |

## ما يفرضه SQL وما يفرضه التطبيق

- FK مركب للعميل والتصنيف مع manager_id يمنع الجمع بين تبعيتين مختلفتين.
- نقل العميل يتطلب إزالة روابط تصنيفات المدير القديم داخل معاملة النقل؛ التصنيفات نفسها لا تُحذف.
- دور المدير principal/subordinate يحدد نطاقه؛ المجموعة تحدد عملياته ولا تمنحه بيانات مدير آخر.
- رئيسي واحد كحد أقصى عبر فهرس فريد؛ إنشاء الرئيسي الأول في معاملة التجهيز مسؤولية التطبيق.
- الرئيسي لا يحتاج مجموعة. الفرعي يحتاج مجموعة، وعدم منح صلاحية يعني منعها.
- التطبيق يرفض منح principal_only=1 لأي مجموعة فرعية؛ الجداول وحدها لا تفرض تحقق الإذن عند الطلب.
- المجموعات المعطلة أو المؤرشفة لا تمنح صلاحيات. تعطيل المدير ينهي جلسات الإدارة فقط ولا يوقف خطوط العملاء.
- التبعية للفرعي تُؤخذ من جلسة المدير، ولا يقبل التطبيق تزوير manager_id أو تجاوز نطاقه.
- created_by_manager_id مستقل عن manager_id حتى يبقى سجل المنشئ صحيحًا بعد النقل.
- لا توجد كلمة مرور افتراضية في SQL. حساب التجهيز يخزن password_hash فقط ويولد كلمة المرور عند التنفيذ لاحقًا.
- payment_code فريد ودائم للعميل، يولده التطبيق ولا يتغير عند تبديل الاسم أو المدير.
- رقم الوثيقة identity_number فريد عند إدخاله، محفوظ كنص حتى لا تضيع الأصفار. المفتاح التقني id ثابت.
- identity_number وبقية الهوية اختيارية؛ القيمة الفارغة تتحول NULL، ولا يمنع غيابها حفظ الاسم والكنية.
- أسماء الهوية تحفظ نسخة الوثيقة ولا تتغير آليًا عند تعديل اسم ملف العميل. QR ميزة لاحقة وليست منفذة بوجود capture_method.
- مرجعا الصور يشيران إلى تخزين خاص؛ ليسا روابط عامة ولا يخزن محتوى الصورة في اللوغ.
- أرشفة العميل ستتطلب معالجة خطوطه عند إضافتها؛ الاستعادة لا تفعّل خدمة تلقائيًا ولا تجمد المدة.
- principal_only والتقاط الهوية والاستحقاق وحقول الأرشفة تحتاج سياسات التطبيق؛ إنشاء الأعمدة لا ينفذها.

## نسخة اشتراك المنصة

platform_subscription.id=1؛ قاعدة الشبكة تخص شبكة واحدة، فلا نضيف tenant_id إلى كل جدول محلي.
central_tenant_id وcentral_subscription_id مراجع منطقية إلى المركز، وليسا FK عابرًا للقواعد.
البيانات المركزية هي المصدر، ولا تسمح واجهة الشبكة بتغيير الحدود أو الرخصة أو التواريخ محليًا.
الحالة pending لا تتضمن تاريخ بداية أو نهاية مُخترعًا؛ تُزامن التواريخ بعد تحقق الجاهزية.
التجديد يستبدل النسخة الحالية مع تسجيل قبل/بعد في اللوغ؛ تاريخ الاشتراكات التفصيلي يبقى مركزيًا.

0 في max_pppoe_accounts أو base_max_nas يعني بلا حد؛ زيادة NAS لا تحول غير المحدود إلى محدود.
إجمالي حد NAS المحدود = base_max_nas + additional_nas_capacity؛ لا يدخل الهوتسبوت في عداد PPPoE.
يجب أن يكون مصدر زيادة السعة هو الإضافات المركزية المعتمدة، لا أسماء الإضافات أو أسعارها.
sync_version رقم متزايد صادر من المركز. آلية توليده وتسليمه لم تُبرمج بعد، ولا نستنتجه من وقت الجهاز.
يطبق التحديث بشرط أن يكون الإصدار الوارد أحدث، في معاملة تشمل سجل النشاط؛ القديم يُرفض.
انقطاع الاتصال بالمركز لا يوقف خدمة البيئة المحلية؛ انتهاء الاشتراك سياسة مستقلة لا نحسمها هنا.

## اللوغ

actor_kind يميز المدير عن العامل الآلي. target_type/target_id مرجع متعدد الأنواع منطقي.
account_id مؤجل إلى تثبيت سجل الخطوط؛ لا نربطه بجدول تخميني.
لا يحفظ كلمات المرور أو أسرار RADIUS/OpenVPN أو صور الهوية أو محتويات الهوية الحساسة.
السجل إضافة فقط عبر التطبيق وصلاحيات حساب القاعدة؛ الجدول لا يمنع UPDATE/DELETE بذاته.
كل تغيير يكتب في اللوغ في المعاملة نفسها. الإجراء الفاشل يسجل بعد التراجع عن معاملته.

## النسخة الموحدة الكاملة

اكتملت جداول الخدمات وNAS وOpenVPN في `create_tenant_database.sql`، وهو ملف الإنشاء المعتمد
للقاعدة الجديدة بدل تنفيذ هذا الجزء وحده. التوثيق الكامل في `docs/tenant-database-template.md`.
لا تُطبق ملفات الإنشاء كترحيلات فوق قاعدة قديمة أو فوق بعضها.

أضيف actual_usage_seconds إلى الوحدات للمحافظة على قرار الهوتسبوت السابق: الشهر في الوقت
المتواصل تقويمي، وفي رصيد الاتصال الفعلي 30 يوم استخدام. PPPoE يظل تقويميًا للشهر.
أضيف توقيت الشبكة وعنوان RADIUS لإعداداتها، والحمولة الموقعة لنسخة اشتراك المنصة.
لم يُنفذ SQL على قاعدة تشغيل، ولا يمثل إنشاء الجداول تفعيلًا للرخصة أو للخدمة.
