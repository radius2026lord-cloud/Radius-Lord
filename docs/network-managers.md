# إدارة مستخدمي الشبكة

داخل بيئة الشبكة تظهر للمدير الرئيسي صفحات «المستخدمون» و«مجموعات الصلاحيات».
ابدأ بإنشاء مجموعة ثم أضف مستخدمًا فرعيًا باسم دخول فريد ومجموعة مفعّلة.
يدخل المستخدم من صفحة الدخول المشتركة؛ التحقق من كلمة مروره يتم في قاعدة بيانات شبكته فقط.

- تستخدم الصفحات جداول managers وpermission_groups وpermissions وpermission_group_permissions الحالية دون تغيير المخطط.
- لا تسمح العمليات بإنشاء مدير رئيسي آخر أو تعديل/تعطيل حسابه.
- جميع عمليات الإدارة محمية على الخادم للمدير الرئيسي، حتى لو عُدّل الطلب يدويًا.
- لا تعرض كلمات المرور أو التجزئات؛ التخزين bcrypt، ولا يسجل سجل النشاط أسرارًا.
- تغيير المستخدم أو مجموعته يبطل جلساته القديمة. تعطيل مجموعة يمنع دخول أفرادها. إعادة التفعيل لا تعيد الجلسات الملغاة.
- لا تغيّر هذه العمليات ملكية العملاء أو حسابات RADIUS أو تشغيل الخدمات.
- دليل الدخول المركزي يخزن مسار البيئة ومعرّف المستخدم واسم الدخول فقط. الأسماء القديمة بعد التعديل لا تقبل الدخول؛ حجوزات الأسماء تُحفظ لتجنب تصادم الحسابات عند فشل حفظ موزع.
- إنشاء حساب فرعي يستخدم كلمة مرور يحددها المدير؛ فرض تغييرها عند أول دخول للفرعي غير متاح بعد. تهيئة المدير الرئيسي المؤقتة القائمة محفوظة.
- مجموعات الصلاحيات جاهزة للاستخدام عند بناء الأقسام التالية. صفحات المشتركين والبروفايلات الحالية تبقى محمية للمدير الرئيسي؛ لم يُفتح وصول فرعي غير مقيّد إليها.

المراجعة الحالية: فحص TypeScript للواجهة والخادم وفحص diff. لم تُشغّل اختبارات أو متصفح أو عمليات على قاعدة البيانات الحية، وفق AGENTS.md. جرّب إنشاء مجموعة ومستخدم وتسجيل دخوله، ثم التعطيل وإعادة التفعيل للتحقق من رفض الجلسة القديمة قبل اعتماد الاستخدام.
