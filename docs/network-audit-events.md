# سجل نشاط الشبكة

تُسجل العمليات في `activity_log` داخل قاعدة الزبون المعزولة، وليس قاعدة زبون آخر. سجلات تعديلات المستخدمين والمجموعات والإعدادات واللوغو تُكتب ضمن نفس المعاملة المحلية، مع بيانات قبل وبعد دون كلمات المرور.

أضيف تسجيل دخول مدير الشبكة عبر صفحة الدخول الموحدة والمسار الخاص بالشبكة، والخروج المتحقق من الجلسة، وفشل محاولة الدخول عندما يمكن تحديد قاعدة الشبكة، وتعيين بيانات الدخول الدائمة ضمن معاملتها، وعرض قوائم المستخدمين والمجموعات. أحداث المصادقة تسجل هوية مؤكدة فقط؛ المحاولة الفاشلة لا تُنسب لحساب لم تثبت ملكيته ولا تخزن الاسم المدخل. أحداث المصادقة والعرض تحمل معرف حدث عشوائيًا.

لا تسجل كلمات المرور أو تجزئاتها أو JWT أو رابط التفعيل أو مفاتيح الاتصال. لا يُنسخ جسم الطلب إلى السجل. فشل حفظ سجل الدخول الناجح يمنع إصدار جلسة؛ تعذر حفظ محاولة فاشلة يُظهر حدثًا تقنيًا دون أسرار. الخروج يمسح الكوكي حتى إذا تعذر كتابة السجل، ولا يُعامل طلب الخروج بجلسة غير مؤكدة بوصفه خروجًا مؤكدًا لحساب.

هذه التغطية ليست شهادة بأن كل مسارات المنصة القديمة مسجلة. العمليات الأخرى مثل تفعيل رابط الحساب وتشغيل NAS والتجهيز المركزي تحتاج ربطًا ومراجعة ضمن مراحلها. الطلبات المحظورة بمحدد معدل المحاولات لا تكتب سجلًا منفصلًا لكل طلب. الطلبات مجهولة الشبكة لا تكتب في قاعدة عشوائية. الاستعلام الدوري عن الجلسة وتحميل الصور لا يسجل كحركة مستخدم مستقلة.

قاعدة التطوير المعتمدة: كل عملية عمل جديدة أو تعديل صلاحيات يجب أن يتضمن سجل نجاح، وسجل فشل مناسبًا، والفاعل والوقت والهدف، مع حجب الأسرار. العمليات التلقائية تُنسب إلى system. لا تسجل نجاح عملية قبل التحقق من نجاحها.

لم تُضف واجهة عرض السجل أو سياسة أرشفة وحذف في هذا التعديل. لم يُشغل اختبار متصفح أو اختبار اتصال بقاعدة المستخدم. جزء المصادقة والسجل لا يحتاج حقولًا جديدة. الأرشفة تتطلب ملف customer_000003_archive_policy.sql.

## الأرشفة — المستخدمون والمجموعات

طبّق ملف `src/app/backend/tenant-upgrades/customer_000003_archive_policy.sql` كاملًا على قاعدة `rl_tenant_zone_000003` بعد ترقية الأدوار، مع نسخة احتياطية وإيقاف كتابات التطبيق. لا تتغير قوالب تجهيز البيئات الجديدة.

زر الأرشفة يوقف الحساب أو المجموعة ويبطل الجلسات المتأثرة ويسجل الفاعل والبيانات قبل وبعد. زر الأرشيف يعرض العناصر القابلة للاسترجاع. الاسترجاع مسجل ويعيد العنصر موقوفًا؛ الحساب الرئيسي غير قابل للأرشفة. لا تنقل العملية ملكية العملاء ولا توقف خدمة RADIUS للمشتركين.

الاحتفاظ افتراضيًا 90 يومًا، ويمكن للمدير الرئيسي ضبطه بين 1 و3650 يومًا. التنظيف التلقائي **متوقف افتراضيًا** ويُفعّل من سياسة الأرشيف. تُحسب المدة من تاريخ الأرشفة، ويُفحص الأرشيف عند بدء الخادم ثم كل ساعة. تقليل المدة مع التنظيف المفعّل يجعل السجلات الأقدم مؤهلة في الفحص التالي. يعالج العامل 100 مستخدم و100 مجموعة في كل دورة لكل بيئة متاحة؛ عند توقف الخادم أو عدم توفر البيئة يتأخر التنظيف حتى دورة متاحة.

التنظيف النهائي للحساب يمحو بيانات دخوله وتواصله وملاحظاته الحالية ويزيل أرقامه الإضافية، ويجعل نطاقه غير مفعّل. تنظيف المجموعة يمحو وصفها وصلاحياتها ويستبدل اسمها. يُحدد purged_at، فلا تُعرض هذه العناصر في الأرشيف القابل للاسترجاع ولا يمكن إعادتها. تبقى صفوف مرجعية لأن سجلات المشتركين والتاريخ مرتبطة بمعرفاتها؛ لا ينفذ DELETE يقطع العلاقات أو حذفًا متسلسلًا للعملاء. بيانات النشاط التاريخية محفوظة ولا تدخل في مدة احتفاظ أرشيف الحسابات.

سياسة الاحتفاظ الحالية تخص مستخدمي الشبكة ومجموعات الصلاحيات فقط؛ أرشفة العملاء والتصنيفات وسائر كيانات المنصة تُربط أثناء بناء أقسامها. لا توجد واجهة عرض سجل النشاط في هذا التحديث.

## واجهة السجل والإعدادات

تاب «سجل النشاط» مستقل: بحث باسم المنفذ أو رمز العملية، تصفية النجاح والفشل، صفحات من 50 حدثًا مع مؤشر id ثابت، تفاصيل قبل وبعد، رقم الحدث ومعرفات التتبع المتوفرة، وتواريخ بمنطقة الشبكة الزمنية. فشل التحميل يظهر صراحة مع إعادة المحاولة. لا يوجد تعديل أو حذف لسجلات النشاط عبر الواجهة أو API هذه الصفحة. هذا لا يمنع مسؤول قاعدة البيانات من تعديلها مباشرة؛ التخزين المقاوم للعبث خارج نطاق هذا التعديل.

المدير الرئيسي يرى السجل المحلي كاملًا، والوكيل ذو activity.view يرى أحداثه وأحداث موظفيه في نطاقه، والموظف المخوّل يرى أحداثه فقط. الأحداث التي سجلها المدير الرئيسي لجهة أخرى لا تُعرض تلقائيًا للوكيل، لتجنب كشف بيانات أطراف أخرى. قراءة السجل نفسها تُسجل، وتُحجب مفاتيح كلمات المرور والرموز والأسرار في بيانات التفاصيل قبل الرد.

الأرشيف وسياسة الاحتفاظ انتقلا من إدارة المستخدمين إلى «الإعدادات ← إعدادات الشبكة ← الأرشيف». تبقى أزرار الأرشفة عند السجلات الأصلية، وتظهر الاستعادة في الأرشيف. مستويات الإعدادات: إعدادات الشبكة وإعدادات RADIUS. الثانية تحفظ فترة المحاسبة وسياسة مهلة السماح مع حماية التعارض وتسجيل التعديل؛ لا تدفع هذه المرحلة إعدادات جديدة إلى NAS أو FreeRADIUS العامل تلقائيًا. لا توجد ترقية SQL إضافية لهذه الواجهة، فوق ترقيات الأدوار والأرشيف المطلوبة سابقًا.
