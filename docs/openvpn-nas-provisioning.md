# تجهيز اتصال NAS مع بيئة الكلاود

التوليد الجديد للكلاود المشترك يضيف مرحلة `network_ovpn` قبل تطبيق RADIUS والتفعيل.
تثبت هذه المرحلة نسخة إعدادات الاتصال وحدود الشراء في `network_ovpn_settings` داخل قاعدة الزبون،
وتنشئ أول NAS باسم «الخادم الأول». لا تنشئ بوابة MikroTik جديدة لكل جهاز؛ لكل NAS حساب نفق
وعنوان وشهادة مستقلة على البوابة المشتركة المختارة. تبقى بيانات API للبوابة مركزية.

## الاستخدام

1. حدّث المشروع وأعد تشغيل الواجهة والخلفية.
2. ولّد بيئة تجربة جديدة، أو أعد محاولة بيئة لم تُفعّل بعد. لا تحتاج تغيير القالب المثبت أو استيراد ترحيل يدوي.
3. بعد تفعيل حساب مدير الشبكة، افتح بيئة الزبون. قسم «خوادم NAS واتصالات OpenVPN» يعرض الاتصال الأول.
4. نزّل ملف `.rsc` من بطاقة الجهاز واستورده مرة واحدة على MikroTik العميل (RouterOS 6.43+ أو 7).
5. تحقق من الربط. القراءة التلقائية كل دقيقة أثناء فتح الصفحة، وبإمكانك استخدام «تحقق الآن».

البيئات التي كانت جاهزة قبل هذا التعديل لا يجري تغييرها تلقائيًا، وتعرض رسالة واضحة بذلك.
سيناريو الاستضافة المحلي أو المخصص يظل غير متاح للتوليد الآلي؛ لا يُحوَّل إلى الكلاود ضمنيًا.

## حدود الخطة والموارد

- المصدر هو `subscriptions.plan_limits_snapshot`، لا تعريف الخطة القابل للتعديل لاحقًا.
- الحد = `maxNas` + مجموع `quantity * nas_capacity_increment` للإضافات المشتراة الصالحة؛ صفر الحد الأساسي يعني غير محدود.
- واجهة الإضافات الحالية لا تحدد سعة NAS للإضافة، ولذلك تسجَّل إضافاتها بسعة صفر. لا تُستنتج سعة من الاسم أو السعر.
- السعة تحفظ في الرخصة المحلية الموقعة، وفي نسخة الاتصال. الإضافة وإعادة المحاولة تتسلسلان مع العامل والحذف تحت قفل مركزي.
- يُنشأ اتصال فعلي فقط لأول NAS أو عند طلب إضافة جهاز؛ لا تُحجز كامل سعة الخطة مسبقًا.
- إعادة الطلب تستخدم مفتاحًا ثابتًا، وإعادة المحاولة تستكمل NAS الموجود. الجهاز الذي تعثر تجهيزه يحتسب ضمن السعة.
- حجز العنوان يستبعد حجوزات القاعدة المركزية، وعناوين Pool المستخدمة، والعناوين الثابتة في PPP secrets.

## متطلبات البوابة والربط

تحتاج البوابة شهادة CA صالحة مع مفتاح توقيع، وهي CA شهادة خادم OpenVPN المحددة.
حساب API يحتاج قراءة وتعديل PPP والشهادات والملفات، وصلاحية `sensitive` لتصدير المفتاح المشفر.
لا ينشئ المسار CA بديلة لشهادة خادم موجودة. عند غياب CA المناسبة يتوقف بالرمز `OVPN_SIGNING_CA_REQUIRED`.

السكربت يثبت CA وشهادة العميل ومفتاحه، ويضبط OpenVPN TCP والتحقق من شهادة الخادم، ومسار /32
إلى عنوان RADIUS عبر النفق، ثم RADIUS لخدمة PPP والمحاسبة. لا ينشئ PPPoE server أو يغير شبكات LAN.
السكربت يحتوي بيانات اتصال خاصة؛ نزّله من جلسة مدير الشبكة واحفظه بشكل خاص.
يتوقف إذا كانت واجهة النفق موجودة، حتى لا ينشئ نسخة إضافية عند إعادة الاستيراد.

يُدار مسار العودة على Ubuntu تلقائيًا من اتصال SSH الموثوق المحفوظ لمخدم FreeRADIUS. عند تجهيز البيئة أو إضافة NAS، يجمع النظام شبكات الأنفاق المسندة للبوابات ويثبت مسارًا لكل شبكة عبر قفزتها من جهة Ubuntu، ثم يحفظ قائمة المسارات في خدمة systemd دائمة بعد إعادة التشغيل. عند ترك «القفزة من خادم RADIUS» فارغة يستخدم النظام عنوان API للبوابة، ولا يقبله إلا إذا أثبت فحص Linux أنه متصل مباشرة على واجهة الشبكة. يمكن تحديد قفزة IPv4 صريحة عندما تختلف عن عنوان API.

يُرفض التفعيل إذا تداخل نطاق نفق مع نطاق بوابة أخرى أو تعارض مع مسار أكثر تحديدًا عبر قفزة مختلفة. خصص لكل بوابة نطاق OVPN خاصًا وغير متداخل. التحديث يعيد التوفيق بين المسارات التي يديرها Radius Lord فقط؛ ولا يزيل المسارات اليدوية غير المملوكة للتطبيق. افتح منفذي UDP المعروضين للبيئة نحو Ubuntu، وأبقِ مصدر RADIUS بعنوان النفق دون masquerade. نجاح اختبار RADIUS الداخلي لا يثبت وصول جهاز بعيد قبل تطبيق سكربته.

## الحفظ والتحقق والحذف

`nas_tunnels` يحفظ الحجز المركزي، و`nas_ovpn_connections` يحفظ اتصال NAS في قاعدة الزبون.
كلمة مرور النفق والمفتاح الخاص وكلمة فك ملف المفتاح مشفرة بمفتاح التجهيز الحالي.
يتحقق المسار من تطابق مفتاح العميل والشهادة وتوقيع CA وبصمتها عند التصدير، ثم يمسح ملفات التصدير من البوابة.
يضيف كل NAS كعميل مستقل داخل virtual server الخاص بالبيئة، مع PAP وCHAP وMS-CHAP.
لا يُتاح تنزيل السكربت قبل نجاح تطبيق إعداد RADIUS.

«جاهز» يعني اكتمال الإعداد؛ «متصل» يحتاج جلسة PPP/OVPN حقيقية بالاسم والعنوان المحجوزين.
بعد فشل قراءة البوابة لا تعرض الواجهة اتصالًا مؤكدًا، وتنتهي صلاحية قراءة الاتصال القديمة بعد 90 ثانية.
هذا تحقق أثناء فتح الصفحة وليس مراقبة خلفية مستقلة.

حذف البيئة يزيل أسرار PPP والجلسات والشهادات وملفات التصدير المدارة، ثم إعداد RADIUS وقاعدة الزبون وحساباتها.
تُحفظ حجوزات العناوين حتى إتمام تنظيف القاعدة ثم تزال مركزيًا. يبقى الخادم والـPool والـProfile والـCA المشتركة.
إذا انقطع التنظيف يستكمله الطلب التالي، ولا يتجاوز تعارض ملكية عناصر يملكها غير هذا المسار.
