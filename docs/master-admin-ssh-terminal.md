# طرفية SSH للمدير الرئيسي

توجد في الصفحة الرئيسية للـMaster Admin، وفي «النظام ← طرفية SSH».
تستخدم قائمة المخدمات المحفوظة في «خوادم قواعد البيانات». لكل مخدم اتصال
SSH مستقل عن حساب MySQL: عنوان ومنفذ ومستخدم Ubuntu وكلمة مرور أو مفتاح
خاص بصيغة OpenSSH/PEM، وعبارة مرور اختيارية للمفتاح.

## تشغيل التحديث

نفّذ `npm install` في جذر المشروع، ثم في `src/app/backend`، وأعد تشغيل الواجهة
والباك إند. يلزم مفتاح التشفير `GATEWAY_ENCRYPTION_KEY` المستخدم أصلًا لاتصالات
الخوادم. ينشئ الباك إند جدول `server_ssh_connections` عند أول فتح للإعدادات؛
يحتاج حساب القاعدة المركزية صلاحية CREATE لهذا الجدول. لا تُنقل أسرار SSH إلى المتصفح
بعد حفظها ولا تُستخدم حسابات MySQL للدخول إلى Ubuntu.

اختر المخدم، وأدخل بيانات Ubuntu ثم افحص الاتصال. في الفحص الأول يُوقف SSH
قبل المصادقة ويعرض بصمة مفتاح المخدم. طابق البصمة عبر وصول موثوق للمخدم، ثم
اعتمدها وأعد الفحص والحفظ. يمكن عرض بصمات المخدم من وحدة التحكم الموثوقة:

```bash
for key in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$key" -E sha256; done
```

بعد الحفظ افتح الطرفية. يمكن استخدام محررات الشاشة وsudo والأوامر التفاعلية،
وفق صلاحيات مستخدم Ubuntu؛ لا يمنحه النظام صلاحيات root إضافية.

## الجلسة والربط

- التحقق من master_admin في REST وفي ترقية WebSocket، والتحقق من Origin.
- طلب فتح مؤقت صالح لمدة 30 ثانية، لمرة واحدة، مربوط بالمدير والمخدم.
- تثبيت بصمة المخدم في كل اتصال، وتشفير الأسرار بـAES-256-GCM.
- جلسة واحدة لكل مدير، وثماني جلسات SSH كحد أقصى لكل عملية باك إند.
- الفصل بعد خمس دقائق دون إدخال، وبعد ساعة، وعند انتهاء token أو تسجيل الخروج
  أو إغلاق الصفحة، وعند تحديث إعدادات الاتصال.
- تسجيل طلب الفتح والإغلاق وبيانات المدير والمخدم، دون الأوامر أو المخرجات أو الأسرار.
- إخفاق فتح الجلسة لا يمنح نجاحًا وهميًا. فحص الاتصال يفتح PTY فعلية ثم يغلقها.

المسار `/api/admin/ssh/terminal` يستخدم WebSocket عبر نفس أصل الواجهة؛ إعادة توجيه
Next.js الحالية تنقله إلى الباك إند. يجب أن يدعم أي reverse proxy ترقية WebSocket،
وأن تكون `FRONTEND_URL` أصل الواجهة الصحيح. استخدم HTTPS/WSS عند النشر الخارجي.
تذاكر الطرفية والجلسات في ذاكرة عملية الباك إند؛ النشر بعدة نسخ يحتاج sticky sessions.

هذه الخاصية لتنفيذ أوامر الطوارئ يدويًا، ومستقلة عن أتمتة تجهيز بيئات العملاء.
لم تُختبر على مخدم المستخدم؛ فحص TypeScript لا يثبت اتصال SSH الفعلي.
