# خوادم الاتصال — الاتصال ثم التجهيز

صفحة Master Admin: `/Dashboard/connection-servers`.

الإضافة والتعديل صفحات كاملة على نمط نماذج المشروع، تستخدم مكونات الإدخال والقوائم والأزرار المشتركة. القائمة جدول على الشاشات الكبيرة وبطاقات على الهاتف.

## الاستخدام
1. أدخل اسم الخادم، عنوان API واسم المستخدم وكلمة المرور. المنفذ وTLS ضمن خيارات متقدمة.
2. اضغط «فحص الاتصال والمتابعة». ينفذ الاتصال الفعلي ثم يقرأ إصدار RouterOS والـProfiles والـPools والشهادات وخدمات OpenVPN. تُحفظ بيانات الإدارة فقط بعد نجاح المصادقة.
3. اختر عناصر موجودة أو أسماء جديدة للـPool والـProfile وشهادة الخادم، وحدد عنوان OpenVPN العام والمنفذ ونطاق الأنفاق وعنوان طرف الخادم.
4. راجع الملخص ثم اضغط «تطبيق الإعدادات على الخادم». يقوم النظام بإنشاء العناصر الناقصة وتفعيل خدمة OpenVPN ثم قراءة النتيجة وحفظها.

اختيار الموجود لا يغير Pool أو Profile مختلفين؛ يجب توافقهما مع المطلوب. إنشاء شهادة جديدة ينشئ CA مخصصة ثم شهادة خادم RSA-2048. توقيع الشهادة قد يستغرق وقتًا. فشل مرحلة يحفظ آخر خطوة؛ أعد الفحص ثم استكمل بنفس الأسماء. لا توجد معاملة تراجع على MikroTik: العناصر الناجحة لا تُحذف تلقائيًا.

## إعداد الباك إند
- ترحيل `20261005_ovpn_gateway_settings.sql` السابق مطلوب؛ لا ترحيل جديد لهذه الخطوة. إعدادات إضافية محفوظة داخل settings_json.
- عيّن `GATEWAY_ENCRYPTION_KEY` إلى 64 حرفًا بالنظام الست عشري، تمثل 32 بايت عشوائية (`openssl rand -hex 32`). احتفظ بالمفتاح خارج Git وقاعدة البيانات.
- API التقليدي يُفعّل على MikroTik مسبقًا. المنفذ المبدئي 8728 لشبكة إدارة موثوقة؛ TLS على 8729 متاح، ويحتاج شهادة إدارة موثوقة يطابق اسمها العنوان. يمكن إضافة CA خاصة إلى بيئة Node عبر NODE_EXTRA_CA_CERTS؛ لا يتجاوز التطبيق فحص الشهادة.
- دعم المصادقة يبدأ من RouterOS 6.43. قراءة الإصدار تحدد إعداد OpenVPN الواحد مقابل الخوادم المتعددة بدءًا من 7.17. النظام يستخدم API التقليدي دون REST لدعم الإصدارين.

## نطاق التنفيذ
تجهيز خدمة OpenVPN TCP وPool وProfile والشهادات عبر API منفذ في الكود. لا يغير API نفسه أو الجدار الناري أو NAT أو مسارات الشبكات. يجب توفير وصول NAS إلى منفذ OpenVPN. الخدمة تشترط شهادة عميل؛ إصدار شهادات وحسابات NAS وحزمة الربط جزء خطوة ربط البيئة التالية.

التطبيق يحتاج فحصًا حديثًا مرتبطًا بمعرّف المدير وبيانات الاتصال، ويعيد مقارنة إعدادات الخادم قبل التنفيذ. قفل مركزي يمنع تجهيزين متزامنين على عنوان الخادم نفسه. كلمات المرور ومفاتيح الشهادات لا تظهر في النتائج أو سجل النشاط. آخر فحص تاريخي لا يمثل مراقبة حية أو حالة نفق.

لم تطبق الأوامر على خادم المستخدم، ولم تشغل اختبارات أو متصفح وفق تعليمات المشروع. يلزم تجربة المستخدم قبل الاعتماد. لا يزال تخصيص عناوين NAS ومنع تداخل البوابات والمراقبة الحية مرحلة لاحقة.
