# صحة البنية التحتية للكلاود المشتركة

الصفحة: `/Dashboard/infrastructure-health`، خاصة بالـMaster Admin.

## الاستخدام

1. احفظ عنوان المنصة في استضافة المنصة، مثل `http://192.168.88.6:3000`.
2. اختر خادم MySQL للتوليد وخادم FreeRADIUS وبوابة OpenVPN.
3. اختر اتصال SSH المحفوظ لمخدم Ubuntu الذي يعمل عليه FreeRADIUS. تستخدم هذه المرحلة اتصالات SSH الموجودة ضمن خوادم قواعد البيانات؛ يجب أن يشير عنوان SSH إلى نفس مخدم RADIUS. لا يكفي اختيار اتصال لمخدم آخر.
4. في إعداد مخدم FreeRADIUS، أدخل بيانات قاعدة اختبار مستقلة موجودة مسبقًا، باسم يبدأ بـ`rl_infrastructure_`، مثل `rl_infrastructure_radius`. يلزم وجود جداول `radcheck` و`radacct` وحساب اختبار وربط الخدمة بهذه القاعدة. لا تُنشأ القاعدة أو إعداد SQL تلقائيًا بهذا التعديل. لا يجوز استخدام قاعدة مسجلة لزبون.
5. عرّف مصدر الباك إند كعميل RADIUS بنفس السر المحفوظ، واستخدم حساب اختبار مخصصًا. فحص المحاسبة يرسل سجل Stop بمعرف جلسة عشوائي ويقرأ السجل من قاعدة الاختبار المستقلة.
6. اضغط «حفظ الاختيار وفحص البنية التحتية». لا تُتاح عملية توليد البيئة إلا عندما تنجح كل النتائج. تُبطل النتيجة عند تغيير الاتصال أو بعد دقيقة، ويُعاد الفحص في الخلفية عند تسجيل طلب التوليد وعند تشغيل عامل التجهيز.

## الفحوص

- المنصة: استجابة من الواجهة على العنوان المحفوظ، ثم استجابة الخلفية عبر الواجهة. تتم مطابقة هوية التطبيق ومعرف طلب عشوائي، دون اتباع التحويلات. في وضع الدومين تُطبق قواعد التحقق من شهادة HTTPS الافتراضية.
- MySQL: الإصدار 8، ميزانية الاتصالات والاحتياطي، إنشاء قاعدة وحساب مؤقتين، منح الصلاحيات والقراءة والكتابة ثم التنظيف. فشل التنظيف يفشل النتيجة.
- FreeRADIUS عبر SSH: وجود الملف `/usr/sbin/freeradius`، حالة وحدة `freeradius`، ثم `sudo -n /usr/sbin/freeradius -C`. يلزم أن تسمح صلاحيات المستخدم بهذا الفحص دون مطالبة تفاعلية. لا تثبيت ولا تغيير للإعدادات ولا إعادة تشغيل.
- RADIUS: المصادقة ورد المحاسبة الموثق والتحقق من السجل في قاعدة الاختبار المستقلة.
- OpenVPN: اتصال API وقراءة الخدمة والشهادة وPPP Profile وIP Pool الفعلية ومطابقتها بالإعداد المحفوظ والتحقق من وجود عنوان متاح. هذا لا يثبت نجاح اتصال نفق زبون، الذي يلزم اختباره عند تجهيز بيئته.

## حدود المرحلة

هذه بوابة بدء التجهيز، وليست تفعيلًا للبيئة. لا تبدأ مدة الاشتراك ولا تُتاح بيانات الدخول للإرسال بسبب نجاحها وحده. عامل التجهيز الحالي ما زال يتوقف عند `ENVIRONMENT_BOOTSTRAP_PENDING` بعد تجهيز قاعدة الزبون؛ تهيئة المدير والرخصة وربط خدمات الزبون واختبار العزل لم تكتمل بهذا التعديل.

يحفظ عامل التجهيز معرفات مخدمات الفحص في خطوة `infrastructure_preflight`، ويرفض تغييرها عند إعادة المحاولة. يستعمل خادم MySQL المختار بدل اختيار خادم مختلف تلقائيًا. تغيير المخدمات لطلب بدأ سابقًا يحتاج مراجعة مستقلة.

لا يلزم ترحيل جديد؛ تستخدم إعدادات `platform_settings` الحالية. يجب وجود الترحيلات المركزية السابقة وجدول إعدادات SSH الذي تنشئه شاشة SSH الحالية.
